## 三、数据模型要求

### `archive_batches`

至少包含：

```text
id, user_id, name, source_root, source_relative_root,
storage_backend, status,
total_files, total_bytes, processed_files, processed_bytes,
success_files, failed_files, skipped_files,
source_cleanup_status, source_cleanup_requested_at,
source_cleanup_completed_at, last_error,
created_at, started_at, completed_at, updated_at
```

状态至少支持：

```text
scanned, queued, running, paused, completed,
completed_with_errors, cancelled, failed
```

### `archive_objects`

至少包含：

```text
id, user_id, storage_backend, object_key,
sha256, size_bytes, content_type, status,
metadata JSONB, reference_count,
created_at, verified_at, last_error
```

同一账号下使用 `user_id + sha256 + size_bytes + storage_backend` 唯一去重。

### `archive_files`

至少包含：

```text
id, batch_id, user_id, object_id, asset_id,
source_path, relative_path, name, extension, kind,
mime_type, size_bytes, source_mtime, sha256,
status, retry_count, error_code, error_message,
source_deleted_at, created_at, updated_at
```

同一批次内 `relative_path` 唯一。`kind` 至少有：`image`、`video`、`audio`、`document`、`archive`、`other`。

迁移脚本/SQL 必须可重复执行。不要删除或破坏现有表数据。

## 四、服务端实现要求

### 4.1 配置

增加并在 `.env.example` 中说明：

```env
ARCHIVE_STORAGE_BACKEND=cos
ARCHIVE_LOCAL_ROOT=/Volumes/AIGC-Archive
ARCHIVE_ALLOWED_SOURCE_ROOTS=/Users/simon/Desktop/AIGC
ARCHIVE_COS_PREFIX=archives
ARCHIVE_MAX_CONCURRENCY=2
ARCHIVE_MAX_RETRIES=3
ARCHIVE_TEXT_PREVIEW_MAX_BYTES=1048576
```

COS 模式必须复用现有 COS 配置；local 模式目标目录不得位于源目录内。local 与源目录同盘时，API/UI 都要提示不会释放空间。

### 4.2 扫描

`POST /api/archive/scan` 请求：

```json
{"sourcePath":"/Users/simon/Desktop/AIGC/1007视频"}
```

要求：

- 只读，不 hash 全文件、不上传、不删除。
- 返回规范化源路径、显示名、文件数量、总字节数、按 kind 统计、跳过项、风险文件数。
- 可以分页返回条目，不能把文件内容返回给前端。
- 必须拒绝白名单外路径和符号链接逃逸。
- 处理中文文件名。

### 4.3 异步归档

创建批次接口不能在一个 HTTP 请求里上传完整目录。创建接口只负责保存批次和清单，返回 201；start/resume 后由服务端后台任务处理。

单文件处理顺序：

1. 重新 stat，检查文件仍存在、是普通文件、大小/mtime 没变化。
2. `createReadStream` 流式计算 SHA-256，不能 `readFile` 大视频。
3. 根据 SHA-256 + size 查找可用对象。
4. 命中则复用对象，不重复上传；否则上传 COS/local。
5. 使用对象 metadata 保存 SHA-256；上传后做 HEAD/本地校验，至少比较 size 和 sha256 metadata。
6. 成功后写 archive_file/archive_object 状态。
7. 图片/视频可创建 assets 记录，source=`本地目录归档`，并设置 `archive_file_id`。
8. 单文件错误写入 error_code/error_message，批次继续。

默认并发 2，最大重试 3，指数退避。任务状态必须持久化；Node 进程重启后 running/uploading/verifying 状态要恢复为可重试，不得把未完成批次误报为 completed。

如果现有 COS SDK 的简单上传不适合大文件，使用 SDK 的分片/可恢复上传能力；不要自己把整个文件读进内存。

### 4.4 清理源文件

`cleanup-source` 必须单独调用，不能由 start/resume 隐式触发。前置条件：

- 批次全部成功，或用户明确选择仅清理成功项。
- 每个待清理文件有目标对象、大小和 SHA-256 校验结果。
- 当前源文件 stat 与导入时一致；变化则禁止删除。
- 请求包含明确确认字段，最好要求提交批次名或固定确认短语。
- local 与源目录同盘时默认拒绝清理。

只删除成功归档的文件，失败文件保留；更新 `source_deleted_at`；空目录默认不删除。

### 4.5 下载和预览

- 文本预览默认最多 1 MiB，超出只下载。
- 下载必须先按 `user_id + archive_file_id` 鉴权。
- COS 使用现有服务端签名机制或同源流，不暴露密钥。
- 不支持预览的二进制文件仍然可以下载。
