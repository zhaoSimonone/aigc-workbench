## 代理问题的根因与修复（已改代码）

- 根因不是"脚本设了代理"，而是它**读**环境变量后自己实现代理请求时写错了：用 `HTTPConnection` 连代理（因为代理是 `http://`），虽然调了 `set_tunnel()` 建了 CONNECT，但 **`HTTPConnection` 隧道里不做 TLS**，只有 `HTTPSConnection` 会 wrap。结果明文 HTTP 被送到 443，nginx 回 `400 The plain HTTP request was sent to HTTPS port`，且 `Cookie: aigc_session` 明文外泄。
- 修复要点：**连接类按目标站 scheme 选，不能按代理 scheme 选**。目标 https → `HTTPSConnection(proxy)` + `set_tunnel(origin, 443)`；内层请求用相对路径；`Proxy-Authorization` 只随 CONNECT 发一次，不能重复塞进隧道内请求头。代理端口默认值也按代理 scheme 取 443/80。
- 回归：带代理 `auth/me` 200、`check-hashes` 200、真实 multipart 上传 201；清空代理直连同样 200。测试素材已 `DELETE /api/assets/:id` 清掉（204），库内总数回到 1283。
- 教训：环境里 `HTTPS_PROXY=http://127.0.0.1:51970` 是沙箱给的，**不是脚本配置**；先看是谁设置的再判断。以后再遇到 400，看响应体里的 Server 头就能区分是代理拒绝还是 origin 拒绝。
