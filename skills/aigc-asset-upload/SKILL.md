# AIGC 素材上传

将用户明确指定的本地视频或图片上传到 AIGC Shelf。上传前先判断每个文件该进哪个库，再按画面特征生成标题和标签。AIGC Shelf 服务端会把文件写入腾讯云 COS，并把素材元数据写入按用户隔离的数据库；本 Skill 不读取、复制或要求用户提供 COS SecretId/SecretKey。

## 素材库

| 库 | 放什么 | 典型检索 |
| --- | --- | --- |
| `服装库` | 可复用的服装参考图，偶尔视频 | 颜色、品类、领口/衣长/面料 |
| `发型库` | 发型/头饰参考图 | 发色、款式、长度、发饰 |
| `通用片段` | 可直接剪进成片的视频片段 | 发型+服装组合、换装、前段 |
| `GIF 素材` | 叠在视频上做遮挡的 GIF 动画、贴纸 | 遮挡对象、位置、风格 |
| `角色设定` | 某个人物的正脸、场景照、动作、该角色的着装照 | 人物、分类 |
| `我的创作` / `灵感收集` / `项目资料` | 成片、泛参考、工作文件 | — |

「服装库」是可复用的衣服参考；「角色设定」里的服装照是「这个角色穿着某套衣服」。两者不要互相搬运。

发型图只上传一次，`folder=发型库`。若同时属于某个人物，填写 `characterName`（例如蕾姆），同一条素材会同时出现在发型库和该人物相册，不要复制文件。

## 工作流程

1. **只处理用户明确指定的文件。** 消息带附件路径就用这些路径；用户给目录时先列出其中的视频/图片并确认范围，不上传无关文件。

   目录扫描约定：本机 `/Users/simon/Desktop/AIGC` 下的 `服装`、`通用片段`、`发型`、`遮挡` 是「待上传区」，用户持续往里放新素材；已上传的素材会归档到同级 `已上传/` 子目录。**只扫描目录本身的文件，跳过所有子目录（尤其是 `已上传/`）**，不要把归档文件重新上传一遍。

   **扫目录用 `--dir <目录>`，不要写 `*.jpg` 这类扩展名 glob。** 微信保存的图里有 PNG 内容叫 `.jpg` 的，也有 JPEG 内容叫 `.png` 的，扩展名 glob 既可能漏掉文件，又可能在改名后彻底匹配不到任何东西。`--dir` 按媒体白名单收本层文件、跳过子目录和隐藏文件，跟扩展名无关。

   **上传前本地文件的扩展名必须和真实格式一致。** 脚本按**文件头**判断 Content-Type，扩展名错标会告警，但服务端 COS 的对象名取自上传时的文件名，扩展名错了会永久留在对象名上，事后改名也改不掉。收到告警就先把本地文件改名再传。

   **每次扫描待上传区都要走完整的「查—传—归档」三步**，不能只把新文件传上去就算完：

   1. **查**：对目录里每个文件算 SHA-256，批量调 `POST /api/assets/check-hashes`，把命中的和未命中的分开。命中的直接拿到服务端素材名。
   2. **传**：只上传未命中的。命名、打标签照常执行。命中但**内容其实是同一段素材的重新编码**（哈希不同但画面一致）时，以库里已上传的那条为准，不要再传，用那条的服务端名。
   3. **归档**：把两个目录里**所有**已在库的文件的本地文件名改成服务端素材名（保留原扩展名），再移动进 `已上传/`。已上传的也要改名——上一轮遗留的旧名同样要对齐，否则本地和远端对不上，无法用来比对。**加 `--archive` 让脚本自动完成归档并复核**，不要手写改名/移动命令。
   4. 归档后复核一遍：把 `已上传/` 里每个文件重新算哈希查一次服务端，确认「本地文件名 == 服务端名」，有对不上的当场修掉；发现内容字节完全相同的重复文件，删掉命名不正确的那个。
   5. 汇报时说清楚：新增上传了哪些、只是改名归档了哪些、清理了哪些重复。

2. **逐文件判定目标库。** 优先级从高到低，命中即停：

   1. 用户明确指定：「传到服装库」「这些是发型」。
   2. **文件是 GIF（`.gif`）→ `GIF 素材`**。GIF 在本工作台里的唯一用途就是叠在视频上做动态遮挡，没有第二种去向；脚本在没指定 `--folder` 时也会自动把 GIF 放进 `GIF 素材`。
   3. 父目录名提示：父目录名为 `服装` → `服装库`；父目录名为 `通用片段` → `通用片段`；父目录名含 `发型` → `发型库`。
   4. 文件名模式：视频名形如 `发型-服装`，或含 `通用片段`/`换装` 且可复用 → `通用片段`。
   5. 看内容：
      - 主体是发型、头饰、假发片、发型对比图 → `发型库`
      - 主体是服装穿搭、全身/半身服装参考、微信保存的衣服图 → `服装库`
      - 可循环使用的人物表演、换装、前段视频，重点是发型+服装组合而不是剧情 → `通用片段`
      - 正脸、身份锁定、人物设定图 → `角色设定`（缺人物名时才提问）
      - 其他创作参考 → `灵感收集`
   6. **用户已指定人物相册且内容是正脸/场景/动作时，即使画面里有头发或衣服，也进 `角色设定`**，不要误路由到发型库或服装库。

   同一批次可以进不同文件夹。混合素材不要用「整批一个 `--folder` + 整批同一组标签」。

3. **逐文件命名和标签。** 只写画面里看得到的事实，禁止编造品牌、角色身份、购买链接或「很适合剪辑」这类空话。

   - **服装库**：标题 `颜色 + 关键剪裁/面料 + 品类`，8–16 字，不用 `·`，不用文件名。
     例：`淡紫针织露肩鱼尾长裙`（标签：淡紫, 针织, 露肩, 长袖, 鱼尾）、`灰色高领露背针织短裙`、`果绿挂脖抹胸长裙`。
   - **发型库**：标题 `发色（可省略默认色）+ 款式 + 关键发饰`。
     例：`蓝色双麻花辫`、`蓝色高丸子头`、`花冠编发`、`齐刘海长卷发`。标签从发色、款式、长度、发饰里选 3–5 个。
   - **通用片段**：文件名已是语义清楚的中文时**沿用文件名去掉扩展名**，不重拟标题；标签从文件名拆开，并加用途标签 `通用片段`，含「换装」加 `换装`，含「前段」加 `前段`，含「无文字」加 `无文字`。
     例：`蓝色高丸子头-淡紫针织挂脖长裙` → `蓝色高丸子头, 淡紫挂脖长裙, 通用片段`。
   - **GIF 素材**：标题写「遮挡物 + 画面位置」，让人一眼知道这东西盖在哪儿。例：`心形贴纸-胸口位置`、`黑色马赛克-面部`、`闪光星形-右下角`。标签从「遮挡物」「位置」「风格」里选 3–5 个，并加 `遮挡` 用途标签：`心形贴纸, 胸口, 遮挡`。
   - 每个素材 3–5 个标签，上限 5。

   **带动漫角色贴图的成片**优先用 `动漫名-角色名-贴图版-换装-换装两端-场景` 命名：动漫名和 cos 角色名放在最前面便于按 IP 检索，后面照样保留这条片子自己的服装描述；「换装两端」写清楚换装前后的两套造型（三套以上就写「A B C 三套换装」，别只列头尾两套），同一批里有多版时在末尾追加区分词（`-主版`、`-主交付`、`-无贴图`）。例：`五等分的花嫁-中野二乃-贴图版-换装`、`鬼灭之刃-竈门祢豆子-贴图版-换装-玫红裹胸换藏蓝金扣制服`、`Fate-远坂凛-贴图版-换装-牛油果绿抹胸换酒红高领黑短裙-主版`。

   **「换装」是类型标记，必须保留**，用来和纯舞蹈区分开——哪怕后面已经写成「A 换 B」也不能省。非 IP 的成片同理：换装片在标题最前面加 `换装-`，舞蹈/实拍/自拍片则不加或改成对应的类型词。

   **标题长度上限 32 字，目标 24–30 字**（服务端会静默截断到 180 字，不会报错，但网格视图里超过 32 字就会挤成多行）。压缩规则：

   - 换装两端各压到 **3–5 字**，只留能区分两套造型的特征词（颜色 + 品类即可），删掉「制服」「紧身」这类修饰和「贝壳」「网格」这类细节，除非它本身就是辨识点。
   - **场景词默认不写**，只有同一 IP 或同一系列有多版需要区分时才加（例：`-主版`/`-主交付` 之外的 `-手办柜前`/`-室内镜前`）。
   - 不要写 `cos`、`cosplay` 这类英文后缀，服装写到「品类」就够。
   - 砍词优先级：场景词 → 服装两端细节 → 才动 IP 和角色名。`动漫名`、`角色名`、`换装` 三个槽位是核心检索维度，任何情况下不能砍。

   识别方法：贴图通常出现在片头，只在开头几秒出现，要及时取帧。先抽 2–3 帧并把贴图区域放大到 1200px 宽再看；同时读画面上的英文贴图文字（如 `Demon Slayer`、`AKAME GA KILL`、`Fate Cosplay`）。贴图没有文字时，从原视频多取几个片头时间点放大比对发色、眼色、帽子/头饰、项圈、外套颜色等特征，再用 `GET /api/assets` 搜库里已有的同 IP 素材比对封面。**认不准角色就不要写角色名**，只写到动漫一级并在汇报里说明存疑，不要凭印象猜；确实不是作品角色的（coser 自己的二次元头像）同样不写，并说明理由。

   分隔符统一用 ASCII 连字符 `-`，标题里**不要出现 `·` 或 `.`**，所有命名（含主题+场景型和上面的动漫贴图型）一律遵守。

**标题和标签一律用中文，不要照抄片头贴图上的日文或英文。** 贴图上的 `ユーベル`、`鬼滅の刃`、`Fate Cosplay` 只是用来认出角色和作品，认出之后要写成中文常用名：作品写 `葬送的芙莉莲` 而不是 `かぎなど`，角色写 `尤贝尔` 而不是 `ユーベル`。只认贴图文字、不认角色本身时最容易写错——同一个 `ユーベル` 字样在不同作品里指不同角色，`かぎなど` 的ユーベル 和 `葬送的芙莉莲` 的尤贝尔 长得完全不同，必须靠贴图画风和服装特征核对，不能凭读音归一。标签同样用中文。

4. **看图规则。** `WechatIMG*`、UUID、英文乱码一律视为无语义，必须打开图片看画面再命名。视频至少看封面；通用片段在文件名无语义时再截 3 个均匀时间点。GIF 至少看一帧确认遮挡物本体（贴纸/马赛克/光效）和画面位置——只看文件名会把「心形贴纸」和「爱心特效」混为一谈。

5. **先把计划给用户看。** 用简表列出「文件 → 目标库 → 新标题 → 标签」。用户已明确说「把服装目录传进服装库」且文件都在该目录时，可以不再逐张确认，但上传后仍要汇报实际标题。

6. **写临时 manifest，调用脚本。** manifest 允许同一批次里不同文件进不同库、拿不同标题和标签：

   ```json
   {
     "items": [
       {
         "path": "/Users/simon/Desktop/AIGC/服装/WechatIMG848.png",
         "folder": "服装库",
         "name": "淡紫针织露肩鱼尾裙",
         "tags": ["淡紫", "针织", "露肩", "长裙", "鱼尾"]
       },
       {
         "path": "/Users/simon/Desktop/AIGC/通用片段/蓝色高丸子头-淡紫针织挂脖长裙.mp4",
         "folder": "通用片段",
         "name": "蓝色高丸子头-淡紫针织挂脖长裙",
         "tags": ["蓝色高丸子头", "淡紫挂脖长裙", "通用片段"]
       },
       {
         "path": "/Users/simon/Desktop/AIGC/遮挡/default-overlay.gif",
         "folder": "GIF 素材",
         "name": "心形贴纸-胸口位置",
         "tags": ["心形贴纸", "胸口", "遮挡"]
       }
     ]
   }
   ```

   规则：`path` 必须是绝对路径且出现在本次上传文件列表中；`folder` 必须是上表允许的文件夹之一；`name`、`tags` 缺省时回退到 CLI 的 `--name` / `--tags`。旧写法 `--name-map`（每行 `路径|标题`）仍然可用，但混合素材一律走 manifest。非法 folder、path 不在文件列表等问题会明确报错并跳过，不会静默改传到灵感收集。

7. **脚本行为。** 脚本先检查本机会话；会话失效时用 `AIGC_SHELF_EMAIL`/`AIGC_SHELF_PASSWORD` 环境变量或安全提示输入，不要把密码写进命令行、Skill 文件或仓库。上传前对每个文件计算 SHA-256 并批量查询已存在素材，重复内容跳过并报告已存在素材的名称和 ID；同批次内相同内容只上传一次；去重检查失败时停止上传。

   **SHA-256 只挡得住字节相同的文件。** 重新编码、转码、改分辨率都会产生不同哈希但内容一样的情况，`final_output*.mp4` 这类同一段素材的多个导出版本尤其常见。遇到疑似重复（文件名或来源指向同一段素材、时长接近、画面高度相似）时，上传前先用 `ffmpeg` 从两个文件各抽 3–5 帧并排比对；确认内容一致就**不要再传，以库里已上传的那条为准**，并在汇报里指出重复。宁可漏传，也不要在库里制造两条几乎一样的素材。

   **但是收敛比对，不要把同 IP 的候选全部拉下来比。** 收敛策略：先用哈希排除精确重复 → 再按「同 IP / 时长接近 / 分辨率相同 / 同一来源目录」筛出**最多 2–3 条**最像的候选 → 只对这 2–3 条做逐帧比对。同 IP 候选超过 3 条时，宁可只比最像的 3 条，也要把结论和没比到的部分在汇报里说清楚。

   **例外必须比全**：当候选的时长和分辨率都对得上、但来源目录不同、无法确定是不是同一条时，才扩大比对范围，并说明为什么。

8. **汇报。** 等脚本输出每个文件的结果再汇报。成功项必须带素材名称和数据库 ID；跳过项必须说明对应的已存在素材；失败项说明文件名和服务端错误，不把失败说成已上传。

## 效率要求

批量整理常因往返次数过多而拖成几十分钟。按下面几条做，**看画面的准确度不打折，只是少做无谓的往返**。

**1. 查重只用 `POST /api/assets/check-hashes`，不要拉全库找素材。** 把待处理文件的哈希一次性传进去，实测 18 个哈希一批 0.01s。绝不要用 `GET /api/assets` 去库里翻某条素材在不在。

**2. 全库索引只拉一次并落盘复用。** `GET /api/assets?limit=5000` 实测 9–27s、响应 2.1MB（含 1032 条带签名缩略图 URL 的完整 JSON），而且 `search` 参数不生效，传了仍返回全量。需要全库时拉一次存到本地文件，后续在本地过滤，不再重复请求。

**3. 一次拼图看多个候选。** 比对多个素材时用 `ffmpeg` 的 `hstack`/`vstack` 拼成 9 宫格或 16 宫格，**一次 Read 覆盖**，不要一张张读。抽帧本身很快（单帧 0.1s），成本在每张图一次模型往返。

**4. 探测、抽帧、上传合并成一次脚本跑完。** 中间不要回来问，也不要把每一步拆成独立的调用。

**5. 写操作不要省。** 实测 PATCH 改标题 0.5s、`check-hashes` 0.01s、从服务端下载 8MB 视频 0.19s，都很快。**不要为了快而少做校验**——省下的时间抵不上漏掉一条重复素材的代价。

时间花在哪：网络调用基本是亚秒级，真正的大头是模型逐轮往返（读图、解析大 JSON）和反复拉全库。压缩往返次数比压缩网络耗时有效得多。

## 调用

脚本默认使用生产地址 `https://aigc.chatcanvas.online`，可用 `AIGC_SHELF_URL` 或 `--api` 覆盖。

整批同库时直接用 `--folder`：

```bash
# 服装目录 → 服装库（扫目录本层，跳过 已上传/；--archive 归档并复核）
python3 /Users/simon/Desktop/dev/code/aigc-workbench/skills/aigc-asset-upload/scripts/upload_assets.py \
  --dir /Users/simon/Desktop/AIGC/服装 \
  --folder "服装库" --source "本地导入" --archive
```

混合文件时只用 manifest，不要整批一个 folder：

```bash
cat > /tmp/aigc-manifest.json <<'EOF'
{"items":[
  {"path":"/Users/simon/Desktop/AIGC/服装/WechatIMG848.png","folder":"服装库","name":"淡紫针织露肩鱼尾裙","tags":["淡紫","针织","露肩","长裙","鱼尾"]},
  {"path":"/Users/simon/Desktop/AIGC/通用片段/蓝色双麻花辫-黑色吊带裙.mp4","folder":"通用片段","name":"蓝色双麻花辫-黑色吊带裙","tags":["蓝色双麻花辫","黑色吊带裙","通用片段"]}
]}
EOF
python3 /Users/simon/Desktop/dev/code/aigc-workbench/skills/aigc-asset-upload/scripts/upload_assets.py \
  /Users/simon/Desktop/AIGC/服装/WechatIMG848.png \
  /Users/simon/Desktop/AIGC/通用片段/蓝色双麻花辫-黑色吊带裙.mp4 \
  --manifest /tmp/aigc-manifest.json
```

`--folder` 可选值：`灵感收集`、`我的创作`、`角色设定`、`项目资料`、`服装库`、`发型库`、`通用片段`、`GIF 素材`。不传 `--folder` 时，GIF 自动进 `GIF 素材`，其余文件进 `灵感收集`。

其它参数：`--source-url` 保存原视频/参考链接；`--used` 标记已使用；可重复传入 `--parent-asset-id` 关联原素材；目标为 `角色设定` 时用 `--character-name`（必需）和 `--character-category` 指定人物相册与分类。

`--dir` 可重复指定；每个目录取**本层**的图片/视频（跳过 `已上传/` 等子目录和隐藏文件），与扩展名无关。`--archive` 只作用于 `--dir` 指定的目录：把已在库的文件改名成「服务端素材名 + 原扩展名」并移入 `<目录>/已上传/`，再重算哈希复核一遍。

## 安全与边界

- 上传是外部状态变更，只在用户明确要求上传时执行。
- 不读取 `/Users/simon/Desktop/dev/cloud/tencent` 下的凭据文件，不在日志、参数、提交或回复中输出 COS 密钥、密码或完整会话 Cookie。
- 会话文件默认保存到 `~/.codex/aigc-shelf-session.json`，脚本设置为仅当前用户可读；发现权限异常时提醒用户，不复制到仓库。
- 默认单文件限制 2 GB，服务端负责生成视频封面、识别时长和写入数据库。
- 不新建数据库表，不修改素材类型字段，不删除角色设定里的正脸、场景照和动作照。
