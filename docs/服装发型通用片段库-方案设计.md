# 服装库、发型库、通用片段沉淀方案设计

> 本文只定义方案，不直接实现代码。实现时请同时参考：`docs/服装发型通用片段库-低阶模型实施任务书.md`。
>
> 目标：在 AIGC Shelf 工作台新增三个页签，沉淀可复用的服装参考、发型参考和剪辑通用片段；并把 `aigc-asset-upload` 做成能按内容路由、按画面命名和打标签的上传入口。

## 1. 目标与边界

### 1.1 目标

1. 侧边栏新增 3 个工作台页签：**服装库**、**发型库**、**通用片段**。
2. 三个库都是现有图片/视频素材，继续使用 `assets` 表、标签、预览、收藏、详情抽屉和 COS，不新建业务表。
3. 服装库导入本机 `/Users/simon/Desktop/AIGC/服装` 的参考图；上传时按画面特征命名并打标签。
4. 发型库承接当前「角色设定」里已经存在的发型参考图，从人物相册迁出，变成可跨角色复用的发型库。
5. 通用片段库导入本机 `/Users/simon/Desktop/AIGC/通用片段` 的视频，供后续剪辑复用；上传时按画面/文件名特征命名并打标签。
6. 加厚 `aigc-asset-upload`：用户说「上传这些资产」时，先判断该进服装库、发型库、通用片段、角色设定还是普通素材库，再按内容生成标题和标签。

### 1.2 非目标

- 不新建 `outfits` / `hairstyles` / `clips` 表，不改 `assets.type`。
- 不做服务端视觉识别 API，不把自动命名做进浏览器上传链路的第一期。
- 不把 `/Users/simon/Desktop/AIGC` 复制进 Git、`public/` 或 `dist/`。
- 不删除角色设定里的正脸、场景照、动作照；只迁出发型参考。
- 不把角色设定中的「服装」人物分类删掉。人物相册里的服装照是「这个角色穿着某套衣服」；服装库是「可复用的衣服参考」。
- 不重构音乐库、提示词库、视频账号、工作文档。
- 不在文档、前端、日志中写入 COS 密钥、密码或完整 Cookie。

## 3. 产品概念

### 3.1 三个库都是素材文件夹

| 页签 | `assets.folder` 值 | 主要内容 | 典型检索 |
| --- | --- | --- | --- |
| 服装库 | `服装库` | 服装参考静图，偶尔视频 | 颜色、品类、领口/衣长/面料 |
| 发型库 | `发型库` | 发型/头饰参考图 | 发色、款式、长度、发饰 |
| 通用片段 | `通用片段` | 可直接剪进成片的视频片段 | 发型+服装组合、换装、前段、无文字 |

页签文案用「通用片段」，不要用「通用片段沉淀」；「沉淀」是能力描述，不是页签名。

### 3.2 和角色设定的关系

- 角色设定继续只服务人物身份：正脸、场景照、动作、该角色的着装照。
- 发型从角色设定迁出后，不再作为人物相册的一类素材。后续选发型时去发型库，不回角色相册翻。
- 迁出后可保留 `characterName`（例如 `蕾姆`）作为来源提示，同时必须打发型标签。不强制清空人物名。
- 角色设定的「服装」分类保留，不自动把人物服装照搬进服装库。

### 3.3 标签是检索面，不新增字段

三个库都用现有 `tags`，每条 3–5 个，上限 5。不要为颜色、品类、发色新建列。

### 4.3 页面行为

三个新页签都走现有素材网格/列表/详情/上传，不做成音乐库那种独立面板。

差异化文案：

- 服装库副标题：沉淀可复用的服装参考，按颜色、品类和细节检索。
- 发型库副标题：跨角色复用的发型参考，按发色和款式检索。
- 通用片段副标题：可直接用于后续剪辑的视频片段，按发型与服装组合检索。

空状态：

- 无筛选时：说明这个库是做什么的，并提供「上传到本库」按钮。
- 有搜索/筛选时：沿用现有「没有找到匹配素材」。

上传默认文件夹：当前页签是这三个库之一时，上传弹窗的「所在文件夹」默认就是当前库。因此 `LIBRARY_FOLDERS` 必须包含它们。

上传/编辑下拉必须能选到三个新文件夹。进入这三个文件夹时，不要强制填写人物相册和人物分类。

通用片段页可以默认筛选「视频」，但必须仍能看到误传进去的图片。不要做死「只能视频」。

## 5. 命名与标签规范

所有自动命名都只写画面里看得到的事实，禁止编造品牌、角色身份、购买链接或「很适合剪辑」这类空话。

### 5.1 服装库

标题：`颜色 + 关键剪裁/面料 + 品类`，8–16 字，不用 `·`，不用文件名。

示例：

| 画面 | 标题 | 标签 |
| --- | --- | --- |
| 淡紫针织露肩长袖鱼尾裙 | 淡紫针织露肩鱼尾裙 | 淡紫, 针织, 露肩, 长裙, 鱼尾 |
| 灰色高领露背针织短裙 | 灰色高领露背针织裙 | 灰色, 高领, 露背, 针织, 短裙 |
| 淡紫挂脖抹胸包臀裙 | 淡紫挂脖抹胸短裙 | 淡紫, 挂脖, 抹胸, 包臀裙 |
| 果绿挂脖抹胸开叉长裙 | 果绿挂脖抹胸开叉裙 | 果绿, 挂脖, 抹胸, 开叉, 长裙 |

`WechatIMG848.jpg` 这类微信名一律视为无语义，必须看图。

### 5.2 发型库

标题：`发色（可省略默认色）+ 款式 + 关键发饰`。

示例：`蓝色双麻花辫`、`蓝色高丸子头`、`花冠编发`、`齐刘海长卷发`。

标签从发色、款式、长度、发饰里选 3–5 个，例如 `蓝色, 双麻花辫, 长发`。

### 5.3 通用片段

标题优先沿用已经语义清楚的中文文件名，去掉扩展名。

已有模式：`发型-服装`，必要时追加 `-换装` / `-前段` / `-2`。

示例：

- `蓝色高丸子头-淡紫针织挂脖长裙`
- `蓝色低马尾-淡粉露肩长裙-换装`
- `蕾姆风蓝色双麻花辫-黑色吊带裙-前段通用片段`

文件名已经是上述结构时：**不要重拟标题**。标签从文件名拆开，并加用途标签：

- `蓝色高丸子头, 淡紫挂脖长裙, 通用片段`
- 含「换装」则加 `换装`
- 含「前段」则加 `前段`
- 含「无文字」则加 `无文字`

文件名没有语义时，至少看封面和 3 个均匀时间点，再按 `发型-服装` 命名。

## 6. 上传路由

`aigc-asset-upload` 在真正调用脚本前，必须先给每个文件判定目标库。优先级从高到低：

1. **用户明确指定**：「传到服装库」「这些是发型」。
2. **路径提示**：
   - 父目录名为 `服装` → `服装库`
   - 父目录名为 `通用片段` → `通用片段`
   - 父目录名含 `发型` → `发型库`
3. **文件名模式**：视频名为 `发型-服装` 或含 `通用片段` / `换装` 且是可复用片段 → `通用片段`
4. **看内容**：
   - 主体是发型/头饰/假发片/发型对比图 → `发型库`
   - 主体是服装穿搭、全身/半身服装参考、微信保存的衣服图 → `服装库`
   - 可循环使用的人物表演/换装/前段视频，重点是发型+服装组合而不是剧情 → `通用片段`
   - 正脸、身份锁定、人物设定图 → `角色设定`（缺人物名时才提问）
   - 其他创作参考 → `灵感收集`
5. 用户已指定人物相册且内容是正脸/场景/动作，即使画面里有头发或衣服，也进角色设定，不要误路由到发型库/服装库。

同一批次可以进不同文件夹。禁止再用「整批一个 `--folder` + 整批同一组标签」处理混合素材。

## 7. Skill 加厚设计

### 7.1 仍然走现有上传 API

脚本继续 `POST /api/assets`，服务端负责 COS、封面、时长、去重。Skill 不读 COS 密钥。

### 7.2 新增逐文件清单 `--manifest`

推荐 JSON：

```json
{
  "items": [
    {
      "path": "/Users/simon/Desktop/AIGC/服装/WechatIMG848.jpg",
      "folder": "服装库",
      "name": "淡紫针织露肩鱼尾裙",
      "tags": ["淡紫", "针织", "露肩", "长裙", "鱼尾"]
    }
  ]
}
```

规则：

- `path` 必须是绝对路径，且出现在本次上传文件列表中
- `folder` 必须是允许的文件夹之一
- `name`、`tags` 缺省时回退到 CLI 的 `--name` / `--tags`
- 保留旧的 `--name-map`（`路径|标题`），但新流程优先用 manifest
- `--folder` 白名单扩展为：`灵感收集, 我的创作, 角色设定, 项目资料, 服装库, 发型库, 通用片段`
- 去重、会话、2GB 限制、成功/跳过/失败汇报保持不变

### 7.3 Agent 工作流

1. 只处理用户指定的文件或目录；目录要先列出再确认范围。
2. 对每个文件做路由 + 命名 + 标签；已有清晰中文名则沿用。
3. 先把计划（目标库、新标题、标签）用简表给用户看。用户已经明确说「把服装目录传进服装库」且文件都在该目录时，可以不再逐张确认，但仍要在上传后汇报实际标题。
4. 写临时 manifest，调用脚本。
5. 按文件汇报：成功必须带标题和数据库 ID；跳过必须带已存在素材；失败不能说成已上传。
