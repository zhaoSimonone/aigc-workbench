# 素材库 API 与工作流改进需求（来自实际使用视角）

> 文档日期：2026-11-02
> 视角：**调用方 Agent**（非人类用户）——批量把 Instagram / TikTok 视频下载 → 看画面识别 IP 与角色 → 按规范命名打标签 → 上传到「灵感收集」→ 回读校验。
> 全部结论均来自 2026-11-02 这一轮真实执行（4 条视频下载识别上传 + 1 条角色二次定性 + 4 条存量素材改名），每条都附了代码位置或实测数据。
> §1–§6 覆盖 **API 与工作流**；§7 补记 **内容识别链路与本机运行环境** 的实战踩坑（这部分不写代码位置，而是写"试过什么、为什么失败、代价多大"）。需求条目共 21 条。

---

## 1. 背景

### 1.1 项目现状

| 项 | 实测值 |
|---|---|
| 服务端 | `server/src/index.js`（Express + PostgreSQL），素材相关端点 18 个 |
| 客户端技能 | `video-inspiration-import`（下载/识别/上传编排）、`aigc-asset-upload`（上传与哈希去重）、`aigc-asset-organize`（存量整理） |
| 素材库总量 | 1388 条（本次操作前后一致，未增未减） |
| folder 分布 | 灵感收集 505 / 我的创作 351 / 角色设定 338 / 发型库 121 / 通用片段 45 / 服装库 27 / GIF 素材 1 |
| 角色字段 | `characterName` 非空 459 条（主要在 角色设定 / 发型库 两个库） |
| 备注字段 | 1382 条仍是默认文案「新上传素材，等待补充备注。」 |
| 标题长度 | **100 条超过 32 字**（规范上限 32、目标 24–30） |
| 标签数量分布 | 1 个标签 701 条、2 个 220、3 个 171、4 个 115、5 个 178、**6 个 2 条、0 个 1 条**（规范要求 3–5 且必含作品名+角色名） |

### 1.2 我实际跑通的链路

```
yt-dlp（复用内置浏览器登录态）→ 本地 media.mp4 + 预览帧
  → ffmpeg 抽帧人眼判读（识别 IP / 角色 / 换装两端）
  → 命名成「作品名-角色名-贴图版-换装-A换B-场景」，打 3–5 个中文标签
  → upload_assets.py 走 POST /api/assets（SHA-256 预查重）
  → 拉 GET /api/assets 全量回读，逐条比对 标题/标签/folder/sourceUrl/时长
```

这条链路本身是通的，**问题全部出在"回读"和"改写"两端**：库只能整包读、改写入口语义重叠、命名规范零机器校验。

## 2. 痛点

按我实际踩坑的严重程度排序。每条含：现象 → 影响 → 证据。

### P0-1 没有单条素材读取接口，回读必须拉全库

- **现象**：`GET /api/assets/:id` 不存在，实测返回 Express 默认的 `Cannot GET /api/assets/<id>` HTML 错误页（HTTP 404）。
- **影响**：改一条标题后想确认，只能重新拉全库 1388 条 / 1.72 MB / 9–27 秒。本轮改 4 条素材，每次校验都要全量拉；一次会话里我拉了 4 次。
- **证据**：`server/src/index.js` 里只有 `GET /api/assets`（1122 行）、`GET /api/assets/:id/stream`（1168）、`/download`（1183）、`/download-url`（1211），**没有 `GET /api/assets/:id`**。
- **我要的**：一个能按 id 取单条的只读端点。

### P0-2 `GET /api/assets` 无过滤、无分页，查询参数全部失效

- **现象**：`?limit=5000` 不生效，`?search=` 不生效，传了照样返回全量 1388 条。
- **影响**：
  - 找一条素材的唯一办法是拉 1.72 MB 全量再本地过滤；
  - 想问"库里有没有标题含『恶魔高校』的素材"，服务端帮不上任何忙；
  - 列表 SQL 用 3 个 `LEFT JOIN` 子查询做标签/关系聚合（1126–1161 行，代码注释自己写了"素材越多首屏越慢"），无法分页就意味着每次都要付这个代价。
- **我要的**：服务端侧过滤 + 分页，至少支持 `id`/`ids`/`q`（名称+标签）/`folder`/`tag`/`since`/`limit`/`offset`。

### P0-3 `/stream` 返回 307 重定向，官方客户端不跟随

- **现象**：`Client.request('GET', '/api/assets/<id>/stream')` 返回 `status=307, payload=None`——重定向目标丢了，payload 直接变成 None。
- **影响**：想把服务端视频下载下来做逐帧比对（这正是我识别重复素材的必要步骤），必须绕开客户端库再调一次 `/download-url` 拿 COS 签名 URL 自己下。本轮为此临时写了两段一次性脚本。
- **证据**：`skills/aigc-asset-upload/scripts/upload_assets.py` 的 `Client.request`（222 行起）不处理 3xx；`server/src/index.js:1168` 的 stream 是重定向而非直出。
- **我要的**：客户端要么自动跟随重定向并保留最终 URL，要么 stream 直接 200 返回内容/直链。

### P0-4 服务端对命名与标签零校验，规范只存在于 SKILL.md 的散文里

- **现象**：
  - `safeName()`（`server/src/index.js:302`）只把 `\` `/` 换成 `_` 并截断到 **180 字**；
  - `parseTags()`（288 行）按逗号/空白拆分、去重，**上限 30 个**；
  - 规范要求的「标题 ≤32 字」「标签 3–5 个」「标签必须含作品名+角色名」「标题禁用 `·` 和 `.`」「换装两端各 3–5 字」——**一条都不校验**。
- **影响**：不合规标题可以静默入库。库里现在就有 100 条超 32 字、701 条只有 1 个标签、2 条 6 个标签、1 条 0 标签。我这轮写 4 条标题时，只能自己在本地数字数（写脚本 `len(name)`），服务端一句提示都不会给。
- **我要的**：上传/改名时做**字段级 lint**，返回可定位的错误（哪个字段、违反哪条、建议值），而不是靠人读文档。

### P0-5 命名的真源在服务端，但下载清单和 state.json 各存一份副本

- **现象**：`video-inspiration-import` 的清单（`batch-4videos.json` / `batch-4videos-upload.json`）和每条视频的 `state.json` 都各自缓存了 `name` / `tags`；本轮确认角色后改了服务端标题，这三处本地文件立刻与服务端**漂移**。
- **影响**：我不得不手工改 3 个本地 JSON 才让两边一致；任何批量改名都会重复这个劳动，且漂移后没有任何东西会提醒。
- **我要的**：要么本地只存 asset id（真源唯一在服务端）、要么提供一个"从服务端刷新本地记录"的命令。

### P1-6 改标题有两个入口，字段几乎重叠，语义不明

- **现象**：
  - `PATCH /api/assets/:id`（1505 行）：`allowed = ['favorite','used','note','folder','name','source','sourceUrl','characterName','characterCategory','musicTitle','musicArtist','musicSource','musicStatus','musicConfidence','musicEvidence']` + `parentAssetIds`；
  - `PATCH /api/assets/:id/organize`（1719 行）：`name / note / folder / source / sourceUrl / characterName / characterCategory / music*` + `tags`。
  - 两者都能改 name，**只有 `/organize` 能改 tags**（1716–1762 行）。`aigc-asset-upload` 的 SKILL.md 只在第 97 行顺带提了一句「有就一并 `PATCH /api/assets/:id/organize` 改掉」，既没说请求体格式，也没列能改哪些字段；完整字段表只出现在 `aigc-asset-organize` 的 README。我这次是 grep server 源码才确认该用哪个、能改哪些字段。
- **我要的**：一个明确的正规入口 + 另两个标记为 deprecated；两个技能的文档写同一份字段表。

### P1-7 整理技能的批量改名要手写 plan JSON，三步走

- **现象**：`organize_assets.py apply`（434 行）读一个 plan 文件，schema 是 `{items:[{id, before:{...}, after:{...}, reason:"..."}]}`；`normalise_plan`（342 行）要求 **`before` 必须存在且 `after` 的每个键都必须在 `before` 里出现**，且 `reason` 非空。
- **影响**：一次批量改名 = `inspect` 拿快照 → 手写 plan JSON → `apply --plan ... --confirm`，每条都要手拼 before/after/reason。脚本化/Agent 化调用不友好（我这轮 4 条改名是绕过它、直接 PATCH 的）。
- **我要的**：`--set-name` / `--set-tags` 这类直给参数的 CLI 模式，与 plan 模式并存。

### P1-8 `check-hashes` 的响应字段名没文档，我第一次解析全 None

- **现象**：`POST /api/assets/check-hashes` 返回的是 `{"assets":[...]}`，不是 `results`。我按 `results` 解析，**拿到的 ID 全是 None**，排查后才在 server 源码里找到 `.get('assets')`（`upload_assets.py:316`）。
- **我要的**：所有端点的**请求/响应 schema 进文档**，最好有 OpenAPI 或一份 `docs/api.md`。

### P1-9 同一素材的字段在上传响应和列表响应里不一致

- **现象**：上传 `POST /api/assets` 的返回里带 `sha256`；`GET /api/assets` 的列表里**没有 `sha256` 字段**（SQL 查了，但 `hydrateAsset` 只用它拼 `src` 的 `?v=` 参数，不外抛）。
- **影响**：想批量核对"本地文件的哈希是否等于库里那条"，只能再发一次 `check-hashes`。
- **我要的**：列表里给 `sha256`（或至少一个 `hasHash` 标记），两边字段尽量对齐。

### P1-10 tags 顺序不稳定，幂等比对必须当集合看

- **现象**：服务端用 `array_agg(DISTINCT t.name)` 聚合，顺序不保证等于提交顺序。同一批 4 条回读时，`['恶魔高校DXD','换装','棕斗篷','莉雅丝','角色扮演']` 的顺序和我提交的 `['恶魔高校DXD','莉雅丝','角色扮演','换装','棕斗篷']` 不同。
- **影响**：任何"提交后校验是否一致"的脚本如果按顺序比对会误报。
- **我要的**：文档写明"顺序无意义"，或服务端固定排序（按创建时间/名称）。

### P1-11 列表里的时间/大小是加工过的字符串，服务端做不了范围查询

- **现象**：`duration` 是 `"00:12"`、`size` 是 `"3.6 MB"`、`date` 是 ISO 字符串但字段名叫 `date` 不是 `createdAt`。
- **影响**：要找"和这条时长接近、可能重复"的候选素材，只能把全库拉下来在本地算。服务端给不了 `?duration_min=&duration_max=`。
- **我要的**：保留人读的字符串也行，但同时给机器可用的数值字段（`durationSeconds` / `sizeBytes` / `createdAt`）。

### P1-12 错误信息贫瘠，分不清"没登录"和"文件坏了"

- **现象**：
  - `Client.request` 只返回 `(status, payload)`；非 2xx 时 payload 可能是 `None`（我遇到 stream 307 的 `None`），没有 headers、没有原始 body；
  - `Client._load_cookies`（207 行）遇到文件不存在或 JSON 解析失败时**静默返回 `{}`**，和"文件存在但内容为空"无法区分；
  - 会话文件是裸的 `{name: value}`，没有签发/过期信息。
- **我要的**：错误对象里保留 status / body / headers；会话文件解析失败要抛明确错误；会话里带 `expiresAt` 或至少能判断是否过期。

### P1-13 服务端不做媒体校验，验证全靠本地手搓

- **现象**：上传端不校验音轨、时长、解码完整性、静音。本轮我按要求做的是：实际分辨率/时长/音轨 → `-xerror` 全量解码 → `volumedetect` 音量 → `-40dB/0.5s` 静音检测 → 服务端回读，全部是本地 ffmpeg 手工拼的 5 步。
- **影响**：每条视频都要我单独跑一遍，重复劳动；而且"有音轨 ≠ 听感正常"这类判断没有沉淀成工具。
- **我要的**：一个可复用的 `verify` 子命令（输入文件 → 输出结构化校验报告：分辨率/时长/音轨参数/解码错误数/mean-max 音量/静音段数），并支持写进 `note` 或作为 `music*` 之外的元数据。

### P2-14 folder 规则在四个地方各写一遍

- **现象**：客户端 `ALLOWED_FOLDERS` 8 项（`upload_assets.py:22`）、服务端三处 `'成片' → '我的创作'` 映射（363 / 1260 / 1537 / 1723 行共 4 处）、技能文档里的文件夹表——同一个概念分散在 6 个地方。
- **影响**：改一个文件夹名要同步 6 处，漏一处就出现"脚本拒绝上传但服务端接受"的不一致。
- **我要的**：服务端一处定义 → 客户端从服务端拉（或生成一份共享常量）。

### P2-15 `src` 字段三种语义混用

- **现象**（`server/src/index.js:464-474`）：视频 → 相对路径 `/api/assets/:id/stream?v=…`（还需带 cookie）；GIF → 稳定签名 URL；普通图片 → 短期签名 URL。
- **影响**：客户端要靠 `type` + `contentType` 判断该怎么取，逻辑散在各处。
- **我要的**：字段语义统一，或显式拆成 `streamUrl` / `directUrl` / `thumbUrl`。

### P2-16 没有批量更新接口

- **现象**：改 4 条素材 = 4 次 PATCH（本轮就是 4 次串行请求）。
- **我要的**：`PATCH /api/assets` 接受 id 数组批量更新，返回逐条结果。

### P2-17 没有"近似重复"能力

- **现象**：库里同一段视频存在**两种编码各存一条**的情况——旧条 `a53c8167` 是 h264 12.47s，新条 `cf2b6c0e` 是 vp9 12.35s，内容不同但同源同场景。SHA-256 挡不住，库里也没标记。
- **影响**：识别"这是不是重复素材"必须下载服务端视频逐帧比对，代价高（我为此下载了 3 段原视频、拼了 3 张对比图）。技能文档只能靠人遵守"最多比 2–3 条"的收敛规则。
- **我要的**：服务端在上传时记录 `durationSeconds + 分辨率 + sourceUrl`，并提供"疑似重复"候选查询（同一 sourceUrl / 时长±10% / 同 folder）。

## 7. 实战踩坑记录（识别链路与运行环境）

这一节记的是 §2 之外、我这轮真实卡住过的地方。前 6 节是"接口与工作流"，这一节是"内容识别"和"这台机器上的运行环境"。

### 7.1 角色识别是整条链路上最贵的一步，而且没有任何可复用的沉淀

- **现象**：现成路径只有一条——原帖贴图/文案 → 人工查资料。库里 1388 条里大量条目挂着 `待整理` 或原始文件名（`instagram-reel-20260831…`、`instagram-reel-20260901…`），说明识别人工成本长期没有被消化。
- **实战案例**（`DfNBcTnAsbH`，2026-11-01 待识别那条）：原帖文案只有 `Your waifu cosplay 😳`、无 hashtag、仅 1 条评论。我依次试了作者主页、IG 镜像站、TikTok 同号（@luna.sato6）、Google Lens（撞验证码）、Bing / Yandex（重定向或验证码）、搜狗 / 百度 / TinEye 反向图搜（无结果 / 上传被拒 / 0 匹配）——**全部失败**。最后是用户凭经验给出「像恶魔高校DXD的莉亚丝」，再靠中文维基「通常穿着」字段 + 库内旧素材画面里的 `Rias DxD Cosplay` 贴图才坐实。
- **成本**：一次确认跨了 10+ 个外部来源、3 轮浏览器操作、4 次全库扫描，**没有一个环节可以复用**。这正是本轮需要改进需求 18/19/21 的原因。
- **技术障碍**：IG 的 CDN 链接带签名且要 Referer，外站根本抓不到；我用 `https://images.weserv.nl/?url=<原图URL>` 做代理，本地 fetch 才通过，但各反向图搜引擎仍各自失败（搜狗/百度上传接口枚举 `ris_upload`/`upload`/`ris` × `file`/`image`/`upload`/`pic` 全部 500；百度 `/upload` 返回 `{"status":1,"msg":"Reject"}`）。

### 7.2 整个项目默认长在 `~/.codex/` 下，换个运行时就得逐个覆盖环境变量

- **现象**：三个技能的脚本默认值全是 `~/.codex`——
  - `aigc-asset-upload/scripts/upload_assets.py:20`、`aigc-asset-organize/scripts/organize_assets.py:20`、`video-overlay-censor/scripts/fetch_overlay.py:27` 的 `DEFAULT_COOKIE_FILE`；
  - `video-inspiration-import/scripts/import_video.py:70-71` 找 `~/.codex/video-inspiration-venv/bin`、`~/.codex/bin`；
  - `import_video.py:359` 回退到 `~/.codex/skills/aigc-asset-upload/scripts/upload_assets.py`；
  - 三个技能的 SKILL.md 也都写死 `~/.codex/...`（会话文件路径、venv 安装命令）。
- **影响**：在 MiniMax Code 里运行时目录是 `~/.minimax/`，我每次调用都得显式传 `AIGC_SHELF_COOKIE_FILE`、`YT_DLP_PATH`、`FFMPEG_PATH`、`FFPROBE_PATH`、`AIGC_UPLOAD_SCRIPT`；否则脚本会去找一个不存在的 `~/.codex` 路径——更糟的情况是**读到别人留下的旧会话**。
- **对应需求**：§3.1 第 17 条。

### 7.3 本机网络与依赖的坑（不属于项目缺陷，但影响可复现性）

- 系统走代理 `HTTPS_PROXY=http://127.0.0.1:7890`；直连 `zh.wikipedia.org` 会一直挂住，只能改走 web_search 或带代理的 fetch。
- **`SSL_CERT_FILE=/etc/ssl/cert.pem` 是必需项**：系统 Python 的 openssl 证书目录是空的，不设这个变量发 HTTPS 会证书校验失败（venv Python + 该变量可直接发 HTTPS 请求）。
- Homebrew 不可用；`raw.githubusercontent.com` 全站 404；`evermeet.cx` 已 410；系统没有 `timeout` 命令（要自己用 Python 实现超时）。
- DuckDuckGo HTML 端点 `https://html.duckduckgo.com/html/?q=` 可用（venv Python + SSL_CERT_FILE）；而 `web_search` 工具在本次会话前段持续报 `MATRIX_TOOL_REQUEST_FAILED`，后半段才恢复——**不要把某个搜索通道当成唯一依赖**。

### 7.4 内置浏览器的约束：看画面这件事在当前环境闭不了环

- provider 是 `electron-file-panel`：`navigate` 在空白 tab 会失败，要用 `open_tab`；没有 tab 切换动作，想回到旧 tab 只能再次 `open_tab` 复现。
- 浏览器工具**无法注入 cookie**，所以 AIGC Shelf 在内置浏览器里始终是未登录态 → 我截不到「灵感收集」列表页的图，只能靠 API 取数据、靠本地 ffmpeg 抽帧看画面。
- 结论：**看画面必须靠本地抽帧 + 读取图片，不能指望浏览器截图闭环**。这也是 §7.1 里那些外部检索通道全部失败的背景。

### 7.5 我自己的操作教训（同样值得写进规范）

- 用 `rm -f of*.jpg` 清临时帧被安全策略拦截（通配符被判定为危险删除目标）→ 改用 `mavis-trash -- "<target>"`，或直接换目录。
- 抽帧临时目录散落在 `/tmp/g1`、`/tmp/g2`、`/tmp/v4`，没有约定 → 建议按 §3.1 第 20 条统一到 `<download-dir>/.identify/` 并在结束时清理，别和素材缓存混在一起。

### 7.6 2026-11-02 晚间按新版技能跑通全流程后，新发现的 4 个问题

新版技能（`shelf_client.py` + `import_video.py` 重写）跑通了「下载 → 校验 → 转码 → 识别 → 命名 → 上传 → 回读」，但暴露了 4 个新问题：

1. **客户端把布尔值编码成 `True`，服务端只认小写 `true`**。
   `Client.list_assets(confirmedCharacter=True)` 经 `urlencode` 变成 `True`，服务端直接 400 `confirmedCharacter 必须是 true 或 false`。
   绕过办法是传字符串 `'true'`，但这属于"调用方要记得手改"的坑，应该由客户端统一小写化。**对应需求 22。**

2. **同名不同字节的近重复会绕过 SHA-256 去重**。
   Instagram 同一条 reel（`DactUk9Ayv3`），库里存的是 2026-11-01 传的 VP9 原流（sha256 `8aecab09…`、2,975,365 B），本次重新下载的 VP9 原流 sha256 是 `4836f3df…`，**字节数、时长、sourceUrl 完全一致但哈希不同**（IG 侧 CDN 同一条视频两次下发字节不同）。
   技能里"按原件哈希命中旧素材"的机制因此失效：TikTok 那条命中了（哈希相同 → `existing`），IG 这条会新传一条 H.264 副本，制造两条几乎一样的素材。
   服务端已有 `similarTo` 查询（`sameSourceUrl` / `sameFolderAndDurationWithin10Percent`），但**上传前的客户端预检没有用它**。**对应需求 23。**

3. **库内存量条目是站点原流，不是兼容副本，QuickTime 播不了；技能却把"替换"推给用户却没给路径**。
   库里那两条存的是 VP9 / HEVC 原流（2.8 MB / 2.5 MB），而新流程交付的是 H.264/yuv420p + AAC（10.2 MB / 12.3 MB）。SKILL.md 写「这不会替换线上旧文件，若需要替换应另行处理」，但：
   - 整理技能 CLI 只有 `--set-name` / `--set-tags`，**没有替换文件的入口**；
   - 服务端其实有 `POST /api/assets/:id/file`（+ finalize）可替换文件，技能层没有封装。
   **对应需求 24。**

4. **整理技能写不了角色字段，新加的 `characterCandidates` 在存量素材上补不齐**。
   `organize_assets.py apply` 只支持 `--set-name` / `--set-tags`；`characterName` / `characterCandidates` 只能绕过技能直接 PATCH `/api/assets/:id/organize` 才能写。库里 1389 条中有 930 条 `characterName` 为空，新加的角色检索能力（`?characterWork=…&confirmedCharacter=true`）基本无从命中。**对应需求 24。**
