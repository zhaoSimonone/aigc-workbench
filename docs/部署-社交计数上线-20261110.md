## 一、私密配置

服务器凭据不进 Git，落在仓库根的 `.env.local`（权限 0600）：

```bash
cd /path/to/aigc-workbench
umask 077 && cp <你的私密配置模板> .env.local && chmod 600 .env.local
git check-ignore -v .env.local   # 必须命中 .gitignore 的 .env.* 规则
```

仓库 `.gitignore` 已忽略 `.env`、`.env.*`、`*.pem`，`.env.local` 不会被跟踪。
私钥不落盘到仓库：运行时从 `.env.local` 的 `SSH_PRIVATE_KEY` 还原到临时文件（0600），用完删除。

## 二、依赖安装

### 本机

| 依赖 | 用途 | 校验命令 |
| --- | --- | --- |
| OpenSSH 客户端 | 连服务器、传补丁与源码 | `ssh -V` |
| `rsync`/`scp` | 传前端源码与补丁 | `rsync --version` |
| yt-dlp / ffmpeg / ffprobe | 采集与转码（技能依赖） | 见技能 runtime 说明 |
| Python 3.9+ | 跑采集脚本 | `python3 -V` |

本机没有 `sshpass` 也不需要：优先用私钥认证，私钥可用 `ssh-keygen -y -f <key>` 校验格式。

### 服务器

| 依赖 | 用途 | 校验命令 |
| --- | --- | --- |
| Docker + Compose | 跑 API 与 PostgreSQL | `docker --version; docker compose version` |
| Node 18（系统自带） | `node --check` 语法校验 | `node --version` |
| node:22 Docker 镜像 | 构建前端（vite 8 要求 Node ≥ 20.19，系统 Node 18 装不动） | `docker images node:22-alpine` |

前端构建不需要在服务器装 Node：


## 三、部署步骤

### 1. 备份（先做，缺一不可）

```bash
REL=/opt/aigc-shelf/releases/social-metrics-20261110
sudo mkdir -p $REL/baseline-src && sudo chown -R ubuntu:ubuntu $REL
sudo cp -a /opt/aigc-shelf/server/src/index.js $REL/baseline-src/index.js
sudo cp -a /opt/aigc-shelf/server/schema.sql  $REL/baseline-src/schema.sql
sudo cp -a /opt/aigc-shelf/frontend              $REL/frontend.before
sudo docker exec -i aigc-shelf-db-1 pg_dump -U aigc_shelf -d aigc_shelf -Fc > /tmp/db-before.dump
sudo mv /tmp/db-before.dump $REL/database-before.dump && sudo chmod 600 $REL/database-before.dump
sudo docker tag aigc-shelf-api:latest aigc-shelf-api:rollback-social-metrics-20261110
# 备份必须用 pg_restore --list 验过才算数
sudo docker exec -i aigc-shelf-db-1 pg_restore --list < $REL/database-before.dump | wc -l
```

### 2. 打增量补丁，不整文件覆盖

服务器上的 `server/src/index.js` 有一处**服务器本地定制**（百度网盘上传提示文案里的本机路径），
仓库里没有。整文件覆盖会丢掉它，所以只应用本次改动的补丁：

```bash
git diff HEAD~1 HEAD -- server/src/index.js > /tmp/social_metrics_index.patch
scp /tmp/social_metrics_index.patch ubuntu@HOST:/tmp/
ssh ubuntu@HOST 'cd /opt/aigc-shelf/server && patch --batch --dry-run -p2 < /tmp/social_metrics_index.patch'
# 干跑通过后再正式应用；-p2 是因为补丁路径是 server/src/index.js
patch --batch -p2 < /tmp/social_metrics_index.patch
node --check src/index.js
```

`schema.sql` 与仓库版本除本次新增列外完全一致，可整file覆盖。

### 3. 应用 schema（幂等）

```bash
sudo docker exec -i aigc-shelf-db-1 psql -v ON_ERROR_STOP=1 -U aigc_shelf -d aigc_shelf \
  < /opt/aigc-shelf/server/schema.sql
```

新增语句是 `ALTER TABLE assets ADD COLUMN IF NOT EXISTS social_metrics JSONB NOT NULL DEFAULT '{}'::jsonb;`，
可重复执行。存量素材的 `social_metrics` 一律是 `{}`，不回填、不改其它字段。

### 4. 重建镜像并重启

```bash
cd /opt/aigc-shelf
sudo docker compose build api
sudo docker compose up -d --no-deps --no-build api
curl -s http://127.0.0.1:18080/api/health
```

### 5. 发布前端

前端是 vite 静态产物，由 Nginx 直接托管 `/opt/aigc-shelf/frontend`，不重建镜像。

```bash
# 上传源码：src/ index.html package.json package-lock.json vite.config.js public/
sudo docker run --rm -v /tmp/fe-build:/app -w /app node:22-alpine \
  sh -c "npm ci --no-audit --no-fund && npm run build"
find /tmp/fe-build/dist -name '._*' -delete      # macOS 元数据文件不要带上
sudo cp -a /tmp/fe-build/dist/assets/. /opt/aigc-shelf/frontend/assets/
sudo cp -a /tmp/fe-build/dist/index.html /opt/aigc-shelf/frontend/index.html
# 清理旧哈希产物
```

## 四、验证方式

### 接口级（可脚本化，最可靠）

```python
from shelf_client import Client
client = Client(API, COOKIE_FILE)
asset = client.get_asset(ASSET_ID)          # 详情返回 socialMetrics
body = json.dumps({"socialMetrics": snap}).encode()
status, payload = client.request("PATCH", f"/api/assets/{ASSET_ID}/organize", body,
                                  {"Content-Type": "application/json"})
```

判定标准：

| 检查 | 期望 |
| --- | --- |
| `GET /api/assets/:id` 的 `socialMetrics` | 有计数的素材返回完整对象，没有的返回 `{}` |
| `PATCH .../organize` 写入后回读 | 与写入完全一致 |
| `{"like": -1}` / `{"like": 1.5}` / `{"unknown": 1}` / `[1,2]` | 一律 HTTP 400，且错误信息指明字段 |
| 数据库 `select count(*) from assets where social_metrics <> '{}'::jsonb` | 与预期回填条数一致 |

### 数据库级（独立于应用层）

```bash
sudo docker exec aigc-shelf-db-1 psql -U aigc_shelf -d aigc_shelf -c \
  "select count(*) from assets where social_metrics <> '{}'::jsonb;"
```

### 产物级

```bash
curl -s https://aigc.chatcanvas.online/ | grep -oE "assets/index-[A-Za-z0-9_-]+\.(js|css)"
curl -s https://aigc.chatcanvas.online/assets/index-<hash>.js | grep -c "平台社交数据"
```

六项数字与采集值一致，未提供的指标显示「未提供」。浏览器控制台不应有未捕获异常。

### 端到端回填

服务端上线后，本地已采集但还没入库的计数用 `metrics` 子命令一次性补齐：

```bash
python3 skills/video-inspiration-import/scripts/import_video.py metrics \
  --manifest "$HOME/Downloads/AIGC-Inspiration/<批次>.json" \
  --results  "$HOME/Downloads/AIGC-Inspiration/<批次>-metrics.json" \
  --api "$AIGC_SHELF_URL" --cookie-file "$AIGC_SHELF_COOKIE_FILE" \
  --proxy http://127.0.0.1:7890 --cookies-from-browser "chrome:/path/to/profile"
```

结果里 `status=updated` 表示本地与线上都写成功；`status=local-only` 表示本地快照已更新但服务端没接受
（通常是服务端还没上线该字段），`status=failed` 表示采集本身失败。

## 五、回滚

本次是新增字段，旧 API 镜像可以继续跑，**不要**为回滚 API 恢复数据库备份，以免覆盖发布后的业务数据。

```bash
cd /opt/aigc-shelf
sudo docker tag aigc-shelf-api:rollback-social-metrics-20261110 aigc-shelf-api:latest
sudo docker compose up -d --no-deps --no-build api
# 前端回滚
sudo rm -rf /opt/aigc-shelf/frontend && sudo cp -a $REL/frontend.before /opt/aigc-shelf/frontend
```

列本身留着无害，服务端不返回也不展示；确需移除再单独 `ALTER TABLE assets DROP COLUMN social_metrics`。
