# 素材首屏性能改造

本报告记录第一阶段。随后完成的三万条容量复核、进一步优化及最终部署结果，
见同目录《容量性能复核-20261103.md》；以下发布版本和容量边界为第一阶段历史记录。

## 基线与目标

2026-11-02 的只读排查：1,401 条素材的 `/api/assets` 返回约 3,001,167 字节；
公网两次耗时 9.41 / 12.06 秒，其中响应体传输 8.91 / 11.59 秒。
服务内部同一接口 160–212 毫秒。客户端接受 gzip，实际响应没有压缩。
现有网页下载全库后只渲染 60 条，搜索、统计、相册和关联选择均依赖全量数组。

目标：首屏网络成本与页大小相关；正常浏览不请求完整素材库；
保留跨页搜索、筛选、中文名称排序、人物相册、关联导航和编辑能力。
实际耗时以发布后实测为准，不把压缩体积估算当作延迟承诺。

## 实施方案

1. 新增独立 `/api/asset-browser` 浏览接口，默认 60、最多 200 条。
   列表仅含卡片字段和一个预览 URL；详情继续用 `/api/assets/:id`。
   旧 `/api/assets` 及其默认全量语义不变，兼容既有 Skill。
2. 服务端按账号及软删除条件查询。支持目录、类型、收藏、使用、
   标签、名称/来源/标签/音乐搜索、人物及分类筛选、稳定排序和分页。
   日期排序使用创建时间、ID；中文名称使用 ICU 中文排序、ID。
   OFFSET 用于当前规模的显式“加载更多”，追加时按 ID 去重；
   并发插入时可刷新回到首页，不承诺跨请求数据库快照。
3. `/api/asset-browser/summary` 返回全库统计、目录数量、标签、
   人物分类数量及小型业务库计数，不依赖当前已加载页。
   人物相册视图由浏览接口的聚合模式返回封面和分组统计，包含空相册，
   保持“角色设定 + 已指定人物的发型库”以及固定封面的语义。
4. 前端服务端查询、搜索防抖、AbortController 和请求代次校验；
   更换条件或成功写入后刷新当前查询及统计。加载更多有独立状态。
   去掉存储完整素材数组的 sessionStorage 缓存，避免超额及过期签名。
5. 详情按 ID 请求；关系和提示词链接按 ID 批量读取；
   上传/编辑参考素材、提示词关联、相册封面选择改为按需搜索分页。
   保留跨页选中项，不能因只显示当前页而丢失既有关系。
6. 提示词、账号和音乐数据按进入对应页面加载；
   首屏不等待它们。摘要保留侧栏计数。
7. 仅在该站点配置 JSON / JS / CSS gzip、Vary；
   不压缩视频，不改变账号隔离和私有响应缓存规则。
8. 增加匹配有效素材按用户和日期分页的部分复合索引。
   不清理素材、不变更对象存储内容、不引入 Redis 或更换数据库。

## 实施前 Review

| 风险 | 审查结论与处理 |
| --- | --- |
| 直接给原请求加 limit 导致统计和搜索漏数据 | 不采用；摘要、搜索、相册由服务端处理 |
| 修改旧 API 默认行为破坏脚本 | 新增网页专用接口；旧路由及响应契约保留 |
| 列表缺少详情字段导致编辑覆盖空值 | 打开详情必须读完整详情后才允许编辑 |
| 引用素材不在首页，链接或选择消失 | 按 ID 查询、分页选择、保留已选 ID |
| 搜索乱序响应覆盖新条件 | 取消旧请求并校验查询代次 |
| 标签/收藏/分类修改后数量及筛选不一致 | 成功写入后刷新列表、摘要及相册 |
| 人物、未分类、发型复用与固定封面退化 | 明确 SQL 语义并做真实数据库验证 |
| 中文排序与数据库默认排序不同 | 用已有 ICU 中文 collation；验证与浏览器顺序 |
| 更大数据量仍出现全量媒体 URL | 列表和选择有上限；摘要不签所有素材 URL |
| 默认全量接口仍较大 | 仅保留给明确需要全量的旧客户端，gzip 同时改善它 |
| gzip 配置扩散到其他站点 | 限定本虚拟主机，nginx -t 后 reload |
| 发布损坏现网 | 镜像/源码/前端/Nginx 配置备份；候选服务验证后切换 |

Review 结论：按上述边界实施；不能把“60 条展示”作为分页验收。

## 验证与发布

- 单元与契约：参数校验、SQL 参数化、用户隔离、字段裁剪、旧 API 回归。
- 隔离数据库：分页集合完整性、跨页搜索/筛选、统计、中文排序、
  空相册/固定封面/人物发型复用、软删除及不同用户隔离。
- 浏览器：桌面及移动尺寸首屏、加载更多、搜索超出首页的素材、
  条件快速切换、详情/关系/选择器、相册、空态/错误态；
  监控网络，首屏不出现无分页 `/api/assets` 或批量视频请求。
- 生产只读：重复采样分页/全量/摘要的 TTFB、总耗时、压缩大小和响应头；
  确认上线代码和镜像与验收一致、未修改已有素材。
- 发布失败：恢复原 API 镜像、前端、Nginx 配置；新增索引保留也兼容旧版。
  不用恢复数据库覆盖上线期间的新业务写入。

## 结果

已于 2026-11-03 完成方案 Review、实施、隔离验收、生产发布和生产只读验证。
基线采样时有 1,401 条素材，发布后实测时有 1,402 条；线上验证没有创建、
编辑或删除素材，验收写入均在独立测试数据库中完成。

### 实测性能

| 项目 | 改造前 | 发布后 |
| --- | --- | --- |
| 网页首批素材数据 | 1,401 条完整数据 | 60 条卡片数据 |
| 列表网络响应体 | 3,001,167 B，未压缩 | 10,607 B，gzip；解压后 51,963 B |
| 列表公网请求耗时 | 9.41 / 12.06 秒 | 0.931 / 0.512 / 0.658 秒，中位 0.658 秒 |
| 全库统计 | 前端依赖完整素材数组 | 独立摘要 5,245 B，中位 0.286 秒 |
| 列表 + 摘要合计 | 完整列表约 3 MB，另有其他业务库请求 | 约 15.9 KB，不含页面静态资源及封面 |
| 旧全量 API | 未压缩 | 保留完整契约；gzip 约 335 KB，中位 1.242 秒 |

首批列表与摘要合计传输量较原完整列表减少约 99.47%。主要收益来自
不再下载全库详情，以及 JSON 压缩。前后网络采样不在同一时刻，
以上不是并发压测，也不把接口耗时等同于整页首屏时间。

生产浏览器使用新建浏览器上下文、现有登录 Cookie，从导航开始计时：

| 浏览器环境 | 60 张卡片已渲染 | 前六张封面已加载 |
| --- | --- | --- |
| 桌面 Chrome，1440 × 1000 | 1.520 秒 | 2.002 秒 |
| WebKit 手机尺寸及触摸模拟，390 × 844 | 1.327 秒 | 1.398 秒 |

两种环境首屏均只有认证、分页列表、摘要三个 API 请求；
未请求完整 `/api/assets`、提示词/音乐/账号库，也未预下载视频流。
上述浏览器计时各一次，未使用网络限速，不代表真实手机弱网的 P95。
封面及视频仍受客户端网络、对象存储访问速度影响。

### 已知边界

首屏不再随素材数量线性增加下载量，但摘要、精确总数和模糊搜索仍需数据库扫描；
本次没有万级/百万级数据及高并发压测，不能据此承诺无限规模。
OFFSET 翻页期间遇到其他客户端新增/删除，仍可能出现跨页位置变化；
前端去重并支持刷新，但不提供跨请求快照。更大规模应根据实际 SQL
耗时和执行计划，再评估游标分页、搜索索引及摘要缓存。
旧客户端明确调用全量接口时仍会收到全库数据。
