# 本地目录归档与工作文档备份方案设计

> 面向 `/Users/simon/Desktop/AIGC` 这类本地创作目录，将视频、图片、工程文件、提示词、脚本、压缩包等统一纳入 AIGC 工作台，作为可检索、可预览、可下载、可恢复的工作文档归档。
>
> 本文只定义方案，不直接实现代码。实现时请同时参考：`docs/本地目录归档与工作文档备份-低阶模型实施任务书.md`。

> **存储策略已修正（2026-10-12）**：大视频默认不再上传腾讯云 COS，也不再由工作台服务器中转。创作目录备份改为本机 MCP 直传百度网盘，工作台只渲染网盘目录。请以 `docs/百度网盘目录渲染与本地MCP归档-方案设计.md` 和 `docs/百度网盘目录渲染与本地MCP归档-低阶模型实施任务书.md` 为准。本文保留为旧版 COS/local 对象存储归档设计。
>
## 1. 目标与边界

### 1.1 目标

1. 在不把素材复制进 Git 仓库、`public/` 或 `dist/` 的前提下，读取本机允许的目录。
2. 支持选择 `/Users/simon/Desktop/AIGC/1007视频` 这样的日期工作文件夹，也支持选择整个 `/Users/simon/Desktop/AIGC`。
3. 保留原始相对目录结构、原始文件名、大小、修改时间、SHA-256 和媒体元数据。
4. 将图片和视频继续纳入现有素材库能力：缩略图、预览、收藏、标签、文件夹、下载、关联创作。
5. 将 Markdown、TXT、JSON、脚本、CSV、DOCX、ZIP 等非媒体文件作为“工作文档”归档，可查看元数据、在线预览文本类文件、下载原文件。
6. 支持 COS 云端备份，以便在确认备份完整后删除本地原文件，真正释放 Mac 本地空间。
7. 支持扫描预览、异步导入、断点续传/重启恢复、失败重试、完整性校验和人工确认删除源文件。
8. 对重复内容去重：相同账号下，同一 SHA-256 + 文件大小只保存一个对象，但保留多个原始路径记录。

### 1.2 非目标

- 不把本地目录直接映射为 Vite 静态目录。
- 不把 `/Users/simon/Desktop/AIGC` 复制到仓库中。
- 不在浏览器端直接访问任意本地路径；浏览器只能调用受服务端白名单保护的扫描/归档 API。
- 不在第一次导入时自动删除源文件。
- 不在没有用户确认和完整校验的情况下覆盖同名文件或删除文件。
- 不将密码、COS SecretId、COS SecretKey 或其他敏感配置写入数据库、日志、前端或文档示例。

## 3. 核心产品概念

### 3.1 归档批次 Archive Batch

一次扫描/导入对应一个批次，例如：

- `1007视频`
- `1008视频`
- `AIGC 全量归档`
- `AIGC/1009换装/工作区`

批次记录扫描源路径、目标存储后端、统计信息、状态、开始/结束时间和错误摘要。

### 3.2 归档文件 Archive File

归档文件是“原始路径记录”，每一个源文件一条记录。它记录：

- 批次和用户
- 源根目录及源相对路径
- 原始文件名
- 文件分类：`image`、`video`、`audio`、`document`、`archive`、`other`
- MIME 类型、大小、修改时间
- SHA-256
- 上传/校验状态
- 目标对象引用
- 是否已生成现有素材记录
- 源文件是否已清理
- 错误信息和重试次数

同一个对象可以被多个归档文件记录引用，从而实现去重并保留原目录结构。

### 3.3 归档对象 Archive Object

归档对象是实际存放在 COS 或本地归档目录中的二进制内容，以 `user_id + sha256 + size_bytes` 做去重键。对象不关心原始文件名，原始文件名由归档文件记录保存。

建议 COS 对象 key：

```text
archives/{userId}/objects/{sha256 前两位}/{sha256}-{sizeBytes}
```

不建议把用户提供的完整相对路径直接当作对象 key，避免中文编码、路径穿越、重命名和特殊字符带来的问题。

### 3.4 工作文档

工作文档是归档文件在界面中的展示概念，不等同于某一种扩展名：

- 图片/视频：既是工作文档，也是现有素材库中的素材，可继续使用现有预览能力。
- Markdown/TXT/JSON/代码/CSV：显示文本预览和下载按钮。
- DOCX/ZIP/DMG/RAW/其他二进制：显示文件元数据和下载按钮，不强行在线解析。
- 音频：显示音频元数据和下载/试听能力；如后续需要，可接入现有音乐库，但本次不改变音乐去重逻辑。

## 4. 推荐总体架构

```text
本机源目录
  │
  │  服务端受控扫描（只读）
  ▼
归档批次 + 归档文件清单（PostgreSQL）
  │
  │  后台任务：hash → 去重 → 上传 → HEAD 校验 → 生成缩略图/素材记录
  ▼
COS（推荐生产备份）或本地归档根目录（开发/临时）
  │
  ▼
工作文档页面 + 现有素材库
  │
  └── 用户确认且全量校验通过后，才允许清理本地源文件
```

### 4.1 存储后端

通过配置选择：

- `cos`：推荐。备份到腾讯云 COS，完成后删除本地源文件可以释放本地空间。
- `local`：仅用于开发或外置硬盘归档。目标目录必须不在源目录内；如果目标和源位于同一块磁盘，复制后不会释放空间，UI 必须明确提示。

建议配置名：

```env
ARCHIVE_STORAGE_BACKEND=cos
ARCHIVE_LOCAL_ROOT=/Volumes/AIGC-Archive
ARCHIVE_ALLOWED_SOURCE_ROOTS=/Users/simon/Desktop/AIGC
ARCHIVE_COS_PREFIX=archives
ARCHIVE_MAX_CONCURRENCY=2
ARCHIVE_MAX_RETRIES=3
ARCHIVE_TEXT_PREVIEW_MAX_BYTES=1048576
```

`ARCHIVE_ALLOWED_SOURCE_ROOTS` 必须是服务端白名单。生产部署在远程服务器时，不应默认允许读取开发机路径；本方案的本地导入模式要求 API 与源目录在同一台可信机器上运行。

### 4.2 为什么不能只新增一个“文件夹”字段

现有 `assets` 表只适合图片/视频，且上传流程是浏览器上传到 COS。如果把所有 `.md`、`.py`、`.zip` 都伪装成视频或图片，会导致 MIME、预览、下载、筛选和数据约束混乱。

因此采用：

- `archive_batches` 管批次
- `archive_objects` 管去重后的实际对象
- `archive_files` 管原始路径和文件条目
- 图片/视频归档成功后，可创建一条现有 `assets` 记录，并通过 `assets.archive_file_id` 与归档文件关联

这样既不破坏现有素材库，又可以覆盖完整工作目录。

## 5. 数据库设计

### 5.1 `archive_batches`

建议字段：

```text
id UUID PRIMARY KEY
user_id UUID NOT NULL
name TEXT NOT NULL
source_root TEXT NOT NULL
source_relative_root TEXT NOT NULL DEFAULT ''
storage_backend TEXT NOT NULL CHECK (storage_backend IN ('cos', 'local'))
status TEXT NOT NULL CHECK (status IN ('scanned','queued','running','paused','completed','completed_with_errors','cancelled','failed'))
total_files INTEGER NOT NULL DEFAULT 0
total_bytes BIGINT NOT NULL DEFAULT 0
processed_files INTEGER NOT NULL DEFAULT 0
processed_bytes BIGINT NOT NULL DEFAULT 0
success_files INTEGER NOT NULL DEFAULT 0
failed_files INTEGER NOT NULL DEFAULT 0
skipped_files INTEGER NOT NULL DEFAULT 0
source_cleanup_status TEXT NOT NULL DEFAULT 'not_requested'
source_cleanup_requested_at TIMESTAMPTZ
source_cleanup_completed_at TIMESTAMPTZ
last_error TEXT NOT NULL DEFAULT ''
created_at TIMESTAMPTZ NOT NULL DEFAULT now()
started_at TIMESTAMPTZ
completed_at TIMESTAMPTZ
updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
```

`source_root` 仅用于服务端审计和展示。若未来支持多用户远程部署，应对路径做脱敏或限制返回；本地单用户模式可以显示完整路径。

### 5.2 `archive_objects`

```text
id UUID PRIMARY KEY
user_id UUID NOT NULL
storage_backend TEXT NOT NULL CHECK (storage_backend IN ('cos','local'))
object_key TEXT NOT NULL
sha256 TEXT NOT NULL
size_bytes BIGINT NOT NULL
content_type TEXT NOT NULL DEFAULT 'application/octet-stream'
status TEXT NOT NULL CHECK (status IN ('pending','uploading','available','verifying','failed'))
metadata JSONB NOT NULL DEFAULT '{}'::jsonb
reference_count INTEGER NOT NULL DEFAULT 0
created_at TIMESTAMPTZ NOT NULL DEFAULT now()
verified_at TIMESTAMPTZ
last_error TEXT NOT NULL DEFAULT ''
UNIQUE(user_id, sha256, size_bytes, storage_backend)
```

`metadata` 保存 COS 自定义元数据、原始扩展名统计等非核心信息，不保存密钥。

### 5.3 `archive_files`

```text
id UUID PRIMARY KEY
batch_id UUID NOT NULL
user_id UUID NOT NULL
object_id UUID
asset_id UUID
source_path TEXT NOT NULL
relative_path TEXT NOT NULL
name TEXT NOT NULL
extension TEXT NOT NULL DEFAULT ''
kind TEXT NOT NULL CHECK (kind IN ('image','video','audio','document','archive','other'))
mime_type TEXT NOT NULL DEFAULT 'application/octet-stream'
size_bytes BIGINT NOT NULL
source_mtime TIMESTAMPTZ
sha256 TEXT
status TEXT NOT NULL CHECK (status IN ('discovered','hashing','queued','uploading','verifying','available','skipped','failed','source_deleted'))
retry_count INTEGER NOT NULL DEFAULT 0
error_code TEXT NOT NULL DEFAULT ''
error_message TEXT NOT NULL DEFAULT ''
source_deleted_at TIMESTAMPTZ
created_at TIMESTAMPTZ NOT NULL DEFAULT now()
updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
UNIQUE(batch_id, relative_path)
```

建议索引：

- `(user_id, created_at DESC)`
- `(batch_id, status)`
- `(user_id, sha256)`
- `(user_id, kind)`
- `(user_id, relative_path)`

在 `assets` 表增加可空 `archive_file_id UUID REFERENCES archive_files(id) ON DELETE SET NULL` 和索引。不要修改现有 `assets.type` 约束。

### 5.4 事务和并发要求

- 建批次、写扫描清单、创建对象引用必须使用事务。
- 文件实际上传不应长时间占用数据库事务；上传前后分别更新状态。
- `archive_objects` 创建必须使用唯一约束和 `ON CONFLICT`，避免并发任务产生重复对象。
- 同一 `archive_file` 只能有一个活跃上传者，可用数据库行锁或状态条件更新实现。

## 6. 扫描、导入、校验和清理流程

### 6.1 阶段 A：扫描（默认只读）

输入：允许白名单内的 `sourcePath`。

扫描规则：

1. `path.resolve()` 后必须位于 `ARCHIVE_ALLOWED_SOURCE_ROOTS` 之一。
2. 使用 `realpath` 检查真实路径，禁止符号链接逃逸白名单；默认跳过符号链接。
3. 只读取常规文件和目录；跳过 socket、设备、FIFO 等特殊文件。
4. 默认跳过：`.DS_Store`、`Thumbs.db`、`.git`、`node_modules`、`.venv`、`.cache`、临时文件。
5. 对 `.env`、私钥、证书、包含 `secret`/`token`/`credential` 的文件名默认标记为敏感并跳过，允许用户在扫描结果中手动选择是否导入；默认不上传。
6. 不读取完整文件内容，只读取 stat、扩展名、MIME 和目录结构；哈希在导入阶段流式计算。
7. 返回文件数量、总大小、按类型统计、预计重复数（已有 SHA-256 能确定时）、跳过数、风险文件数。

扫描阶段必须可以在 `1007视频` 上完成，不产生 COS 对象，也不修改源文件。

### 6.2 阶段 B：创建导入批次

用户在扫描结果中选择：

- 当前目录全部导入
- 只导入某几个一级/二级子目录
- 排除指定后缀或风险文件
- 是否为图片/视频自动创建现有素材记录
- 目标存储后端

创建批次时保存不可变的文件清单。后续导入不能依赖用户继续保持扫描目录不变；每个文件开始处理时都要重新 stat，并检查大小/mtime 是否发生变化。

### 6.3 阶段 C：后台导入

每个文件按以下顺序处理：

1. `stat` 源文件，确认仍是普通文件且大小/mtime 与清单一致。
2. 使用 `createReadStream` 流式计算 SHA-256；禁止 `readFile` 一次性载入大视频。
3. 查询 `(user_id, sha256, size_bytes, storage_backend)` 是否已有可用对象。
4. 已存在：跳过重复上传，直接建立引用。
5. 不存在：上传到目标后端。大文件必须支持临时对象/分片上传或 SDK 的可恢复上传能力。
6. 上传完成后执行目标端校验：至少比较大小和保存的 SHA-256 元数据；本地后端还要再次 hash 或原子 rename 校验。
7. 对图片/视频生成缩略图或沿用现有媒体处理逻辑；不能因为缩略图失败而丢失原文件归档，应该将其标记为可用但媒体处理待重试。
8. 对图片/视频创建现有 `assets` 记录，`source` 建议为 `本地目录归档`，`sourceUrl` 留空，`folder` 使用批次名称或用户选择的目标文件夹，并保存原始相对路径到归档关联数据中。
9. 更新 `archive_files`、`archive_objects`、批次统计。
10. 删除临时文件。任何失败只影响当前文件，不能让整个批次丢失进度。

建议并发数默认 2，按字节数而不是只按文件数显示进度。重试 3 次，指数退避；明确区分文件不存在、源文件变化、权限错误、COS 网络错误、校验失败和不支持类型。

### 6.4 阶段 D：恢复和暂停

- `paused` 不再领取新文件；当前文件完成后停止。
- API 进程重启时，把 `running/uploading/verifying` 状态恢复为可重试状态；不要把批次误报为完成。
- 通过批次 ID 可继续未完成、失败或源文件变化的条目。
- 成功文件不得重复上传；依赖 SHA-256 + size 去重。
- 取消批次只停止未开始的文件，不删除已完成对象；用户可以之后继续或手动清理孤儿对象。

### 6.5 阶段 E：源文件清理

源文件清理必须是单独的显式动作，不能作为导入接口的默认参数。

允许清理的前置条件：

1. 批次状态为 `completed` 或用户明确选择“跳过失败项后完成”。
2. 目标对象全部为 `available`，每个文件都有 SHA-256 和目标端校验结果。
3. 源文件当前 stat 与导入时一致；若文件在导入后被修改，禁止清理并标记 `source_changed`。
4. 生成可下载的清单（批次、相对路径、大小、SHA-256、目标对象 key、校验时间）。
5. 用户在 UI 进行二次确认，明确知道这是删除本机源文件的操作。

清理建议：

- 只删除归档成功的文件，不删除失败项。
- 删除后更新 `source_deleted_at` 和 `source_cleanup_status`。
- 空目录是否删除单独作为选项，默认不删除根目录；只清理已经为空的子目录。
- 任何 `unlink` 失败都要记录并继续处理其他文件。
- 如果目标后端是同一块本地磁盘，UI 必须阻止或强警告“不会释放磁盘空间”，默认不允许清理。

## 7. API 设计

所有接口都必须复用现有 `requireUser` 和账号隔离规则。

### 7.1 扫描

```http
POST /api/archive/scan
Content-Type: application/json

{
  "sourcePath": "/Users/simon/Desktop/AIGC/1007视频"
}
```

返回：

```json
{
  "scan": {
    "sourcePath": "/Users/simon/Desktop/AIGC/1007视频",
    "displayName": "1007视频",
    "fileCount": 287,
    "totalBytes": 618298523,
    "byKind": {"video": 180, "image": 80, "document": 27},
    "skipped": [],
    "riskFiles": [],
    "entries": []
  }
}
```

`entries` 可以分页或只返回前 N 条；不要为了展示扫描结果把所有大文件内容读入内存。

### 7.2 创建批次

```http
POST /api/archive/batches
Content-Type: application/json

{
  "name": "1007视频",
  "sourcePath": "/Users/simon/Desktop/AIGC/1007视频",
  "storageBackend": "cos",
  "includeRelativePaths": ["."],
  "excludePatterns": [".DS_Store"],
  "createMediaAssets": true
}
```

返回 `201` 和 `batch`，批次初始状态为 `queued`，不要在 HTTP 请求中同步上传整个目录。

### 7.3 批次查询和控制

```text
GET  /api/archive/batches
GET  /api/archive/batches/:id
POST /api/archive/batches/:id/start
POST /api/archive/batches/:id/pause
POST /api/archive/batches/:id/resume
POST /api/archive/batches/:id/cancel
POST /api/archive/batches/:id/retry-failed
POST /api/archive/batches/:id/verify
POST /api/archive/batches/:id/cleanup-source
```

`cleanup-source` 必须要求请求体中的批次 ID、确认字符串和服务端生成的确认条件匹配；不要只靠一个布尔值。

### 7.4 文件列表和下载

```text
GET /api/archive/files?batchId=...&kind=document&status=available&page=1&pageSize=50
GET /api/archive/files/:id
GET /api/archive/files/:id/download
GET /api/archive/files/:id/preview
```

文本预览必须有大小上限，默认 1 MiB；大文件只提供下载。下载使用服务端授权后的短期 URL 或同源流，不直接暴露永久 COS 凭证。

## 8. 前端交互设计

### 8.1 新增入口

在现有侧边栏新增“工作文档”或“本地归档”入口，不改变现有 `全部素材`、`我的创作`、`音乐库` 等路由。

### 8.2 扫描/导入弹窗

字段：

- 源目录路径输入框，仅允许白名单前缀
- “扫描”按钮
- 扫描结果：文件数、总大小、类型统计、风险文件、预计重复数
- 子目录/文件勾选
- 目标存储后端
- 图片/视频是否创建素材记录
- “创建归档批次”按钮

提示：

## 9. 安全、稳定性和异常处理

### 9.1 路径安全

- 所有源路径必须 `resolve + realpath`，并校验位于白名单目录内。
- 禁止 `..` 逃逸、符号链接逃逸和读取白名单外路径。
- 归档目标 key 不使用未经处理的用户路径。
- 文件名和相对路径只用于展示/元数据；下载时用数据库对象 ID 查找真实对象。

### 9.2 敏感文件

默认跳过：`.env`、`.pem`、`.key`、`.p12`、含 `secret`/`token`/`credential` 的文件。扫描结果可以展示“已跳过敏感文件数量”，不在日志中打印内容。必须提供明确的人工选择才能导入，但默认实现可以先只支持跳过。

### 9.3 大文件和内存

- hash、上传、下载都使用流。
- 不能把视频或整个目录 `readFile` 进内存。
- 进程内任务队列只保存批次/文件 ID，不保存文件二进制。
- 前端轮询批次进度，不能让一个长 HTTP 请求保持数小时。

### 9.4 日志

日志只输出批次 ID、文件 ID、相对路径、状态和错误类型。禁止输出密钥、Cookie、签名 URL、密码和文件内容。必要时对绝对路径做脱敏。

## 11. 验收标准
